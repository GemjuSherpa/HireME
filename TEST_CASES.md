# HireME test cases

| ID      | Area                   | Scenario                                                                                        | Expected result                                                                | Automation      |
| ------- | ---------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | --------------- |
| C-01    | Candidate profile      | Save a profile with three skills, preferences and valid bio                                     | Profile is accepted and completion score updates                               | Unit/API        |
| C-02    | Candidate profile      | Submit fewer than three core skills                                                             | Validation explains the missing requirement                                    | Unit            |
| C-03    | Privacy                | Recruiter views an anonymous match before invite acceptance                                     | Name and contact details remain hidden                                         | Integration     |
| C-04    | Privacy                | Candidate accepts an invitation                                                                 | Identity is revealed only to that hiring pipeline                              | Integration     |
| M-01    | Matching               | Candidate meets all weighted and verified requirements                                          | High score and human-readable evidence are returned                            | Unit            |
| M-02    | Matching               | Required skill is missing                                                                       | Score is penalised and missing skill is reported                               | Unit            |
| M-03    | Matching               | Skill casing differs                                                                            | Equivalent skill names still match                                             | Unit            |
| A-01    | Assessment             | Candidate completes assessment above cutoff                                                     | Result is scored and candidate advances                                        | Integration     |
| A-02    | Assessment             | Proctoring detects an integrity anomaly                                                         | Result is flagged for human review, never auto-rejected                        | Integration     |
| R-01    | Recruiter              | Recruiter creates a pipeline with stages and deadline                                           | Active job and configured stages are persisted                                 | E2E             |
| R-02    | Recruiter              | Auto-invite batch exceeds configured limit                                                      | Only the allowed number of invitations is sent                                 | Integration     |
| P-01    | Pipeline               | Shortlisting agent applies top-N rule                                                           | Highest eligible candidates advance with audit entries                         | Integration     |
| N-01    | Notification           | Assessment deadline approaches                                                                  | Candidate gets one reminder through enabled channel                            | Integration     |
| S-01    | Security               | Candidate requests another user’s private profile                                               | API responds 403 and writes an audit event                                     | Security        |
| S-02    | Security               | Unauthenticated user accesses dashboard API                                                     | API responds 401 without leaking data                                          | Security        |
| UX-01   | Responsive UI          | Landing page is opened on desktop and mobile                                                    | Content is readable with no horizontal overflow                                | Playwright      |
| UX-02   | Onboarding             | User starts profile creation from homepage                                                      | Professional-story step is displayed                                           | Playwright      |
| OPS-01  | Health                 | Deployment health endpoint is requested                                                         | HTTP 200 with `status: ok`                                                     | CI smoke        |
| AUTH-01 | Authentication         | Correct recruiter credentials are submitted                                                     | A hashed opaque session is stored and an HttpOnly cookie is issued             | Integration     |
| AUTH-02 | Authentication         | Five invalid passwords are submitted                                                            | Account is temporarily locked for 15 minutes                                   | Integration     |
| AUTH-03 | Session isolation      | Authenticated user requests landing, login, or signup                                           | User is redirected to their role-specific workspace                            | Integration/E2E |
| AUTH-04 | Session isolation      | Login or signup is submitted while a browser session is active                                  | Server rejects the request until the active account signs out                  | Integration     |
| AUTH-05 | Role isolation         | Company account requests candidate dashboard                                                    | Request redirects to recruiter workspace                                       | Integration/E2E |
| AUTH-06 | Role isolation         | Candidate account requests recruiter workspace                                                  | Request redirects to candidate dashboard                                       | Integration/E2E |
| REG-01  | Candidate registration | User selects Candidate and completes signup                                                     | Candidate profile is created without a recruiter/company profile               | Integration     |
| REG-02  | Company registration   | User selects Company and completes organization fields                                          | Company and recruiter profile are created without a candidate profile          | Integration/E2E |
| REG-03  | Account type           | User attempts to change role after registration                                                 | Operation is unavailable and server authorization retains original role        | Security        |
| PROF-01 | Detailed profile       | Candidate adds career goals, skills, work, education, projects, certifications and publications | Structured records persist and profile score is recalculated                   | Integration/E2E |
| PROF-02 | Verified evidence      | Candidate updates detailed work history                                                         | Locked verified employment records remain unchanged                            | Integration     |
| PROF-03 | Résumé                 | Candidate uploads a PDF or DOCX under 5 MB                                                      | Private file and checksum metadata are stored; previous résumé is archived     | Integration     |
| PROF-04 | Résumé security        | Another candidate requests the résumé download URL                                              | API responds 404 without exposing file metadata                                | Security        |
| PROF-05 | Résumé validation      | Candidate uploads an unsupported or oversized file                                              | Upload is rejected without writing metadata                                    | Integration     |
| WF-01   | Orchestration          | Recruiter launches a published job                                                              | Top configured candidate pool is ranked and first-stage invitations are queued | Integration     |
| WF-02   | Orchestration          | Candidate passes a stage with sufficient confidence                                             | Next ordered stage is created and invitation email is queued once              | Integration     |
| WF-03   | Human oversight        | Model confidence is below policy threshold                                                      | Application enters `NEEDS_REVIEW`; no autonomous rejection occurs              | Integration     |
| WF-04   | Final selection        | Candidate completes every autonomous stage                                                      | Candidate becomes `FINALIST` for company face-to-face interview                | Integration     |
| WF-05   | Feedback               | Candidate is not advanced                                                                       | Thank-you feedback email is queued with a deterministic deduplication key      | Integration     |
| PWA-01  | Progressive app        | Production app is installed and revisited offline                                               | Core shell, login page and icons load from service-worker cache                | Playwright      |

High-risk flows (identity consent, reference locking, assessment integrity flags and automated rejection rules) require integration tests against a temporary PostgreSQL database before production launch.
